🧠 Reasoning & Thinking Modes
Ultra Think
Magic keyword that forces Claude to spend maximum reasoning effort. Type "Ultra Think" anywhere in your prompt to trigger extended reasoning mode, flagged by a rainbow color indicator.
Use for big planning prompts and complex analysis. Costs significantly more tokens — keep other prompts lighter to compensate.
/insights
Triggers Claude to analyze your last ~30 days of sessions and generates a detailed HTML report: what works, what's slowing you down, and personalized features to try.
Run monthly as a reality check on your Claude usage. Download the HTML report or save it to Drive for reference.
🧩 Tokens & Efficiency
/caveman
Open-source skill that rewrites Claude's output into a shorter, denser style — cutting output tokens significantly by stripping filler and verbose phrasing.
Great when watching usage limits or wanting raw, terse answers. Works best on factual or analytical output.
/clear
Resets the current session context between unrelated tasks. Prevents context bloat so Claude stays sharp and accurate; also reduces token usage over long sessions.
/btw
Short for "by the way" — lets you ask a quick side question without interrupting any long-running task or bloating your main context. Claude answers the aside and returns to the primary thread.
Keeps your main context intact. Useful mid-task when something unrelated pops into your head.
⏱ Scheduling & Loops
/loop
Schedules a recurring local task with a minimum 1-minute interval and maximum 3-day expiry. Runs on your machine while your computer is on — requires local file access and the Cowork environment.
Good for short-loop automations like "draft a post every 5 minutes" or "check a folder every 10 minutes." Stops when your machine sleeps.
/schedule
Cloud-based scheduler with no 3-day expiry. Runs against your plan's daily cap (5 / 15 / 25 runs per day — Free / Pro / Team). Does not require your local machine to be on.
Ideal for daily standups, recurring reports, or automations that should run even when your computer is off.
🛠 Session & Workflow Control
/todos
Shows the current task list or to-do items in the agent's view. Useful during multi-step agentic workflows to see what Claude has queued up or completed.
/tasks
Lists background tasks or subprocesses the agent is currently running. Use to audit what's happening under the hood during complex agentic sessions.
/init
Analyzes your codebase and auto-generates a CLAUDE.md file containing repo-level rules, conventions, and architecture notes Claude should follow in all future sessions on this project.
Run once when starting work on a new codebase. The generated CLAUDE.md acts as a persistent system prompt for the repo — the single highest-impact action for improving Claude Code quality.
/hooks
Opens or edits hook configuration — defining what Claude should do automatically before or after certain actions (e.g., run tests after every code edit, format files before saving).
Set up a "run linter after every edit" hook once and never remind Claude again.
/terminal-setup
Installs the Shift+Enter key binding for multiline input in the terminal version of Claude. Without this, Enter submits immediately, making multi-paragraph prompts awkward in the CLI.
⌨ Keyboard Shortcuts
Ctrl+C
Cancels the current operation. Use when Claude is running a long agentic task and you want to stop it without closing the session.
Ctrl+D
Exits the current Claude session cleanly. Equivalent to typing "exit" — use this in terminal/CLI environments.
Ctrl+T
Toggles the task list panel open or closed. Quick way to check the current to-do queue without typing /todos.
Ctrl+O
Toggles verbose transcript mode — shows the full internal reasoning and tool calls Claude is making. Useful for debugging why an agentic task went wrong.
Shift+Enter
Inserts a newline without submitting. Standard in the web UI; requires /terminal-setup to enable in CLI.
Esc Esc (double)
Opens a rewind or conversation history menu in supported environments, letting you jump back to an earlier state or branch from a previous message.
💻 Claude Code Session Commands
/compact
Compresses conversation history by summarizing older messages while preserving important context. Frees up context window without losing the thread. You can specify what to retain: /compact retain the error handling patterns.
Use at ~80% context usage. Use /clear only when switching to a completely unrelated task. Since v2.0.64, compaction completes instantly.
/model
Switch between Claude models mid-session without restarting. Lets you move from Opus to Sonnet for cheaper tasks and back to Opus for hard ones. Usage: /model sonnet or /model opus.
Use Sonnet for routine edits, refactors, and boilerplate. Switch to Opus for architecture decisions, complex debugging, and anything where quality matters more than cost.
/effort
Controls how much reasoning Claude applies to the current task. Levels: low, medium, high, max. Opus 4.7 also supports xhigh between high and max. Running /effort alone opens an interactive slider.
Default changed to medium for Opus in March 2026 for Max/Team subscribers. Use high or max for architectural decisions, security reviews, or anything where a wrong answer is expensive. Use low for quick lookups and boilerplate.
/fast
Enables speed-optimized mode — runs the same Opus model but with faster API settings. Ideal for rapid iteration and live debugging where you want quick back-and-forth responses.
Turn off when cost efficiency matters. Note: enabling Fast Mode mid-session re-bills the entire prior context at Fast Mode rates, so start it at the beginning of a session if you plan to use it.
/help
Shows all available commands including your custom skills and any commands exposed by connected MCP servers. The output updates dynamically as you install skills and connect servers.
Run this after installing a new skill or connecting an MCP server to confirm it registered correctly. Also useful when you forget the exact name of a custom command you built.
/install-github-app
Sets up automated PR review — Claude will automatically review every pull request and leave comments. Out of the box it's too verbose. Customize the generated claude-code-review.yml to focus only on bugs and security issues.
Suggested prompt: "Review this PR and look for bugs and security issues only. Report only actual bugs and vulnerabilities. Be concise." This prevents Claude from commenting on variable names and style nitpicks.
! prefix (shell passthrough)
Run shell commands directly by prefixing with ! — bypasses Claude's conversational mode entirely. Example: !git status or !npm test. The output goes straight to your terminal.
Saves tokens vs asking Claude to run commands conversationally. Use it for anything you'd normally type in a separate terminal tab — git operations, running tests, checking logs.
@ file references
Tag files or directories directly in your prompts with @filename or @src/components/. Claude loads the exact file content rather than having to search for it.
Always use @ references instead of describing files by content. It's faster, cheaper, and more accurate. Works with directories too — @src/ includes all files in that folder.
CLAUDE.md
A Markdown file that Claude reads at the start of every session. Acts as a persistent system prompt. Two levels: global (~/.claude/CLAUDE.md) applies to all projects; project-level (.claude/CLAUDE.md) applies to that repo only.
Put in: build commands, test commands, architecture overview, coding conventions, things Claude should never do. The project CLAUDE.md is git-versioned — review changes to it in PRs like any other code.
/keybindings
Opens and edits your custom keyboard shortcuts file at ~/.claude/keybindings.json. Changes take effect immediately without restarting Claude Code.
Create shortcuts for commands you type constantly. If you use /compact multiple times per session, bind it to something fast. Changes are live immediately — no restart needed.
⇧ Shift+Tab Mode Cycling
Shift+Tab
Each press cycles through three modes: Normal (default, asks permission for every action) → Auto-accept (executes all actions without asking) → Plan mode (Claude plans and outlines without executing anything). The current mode is shown below the prompt.
Auto-accept is the biggest productivity unlock for trusted tasks — no more coming back to a waiting Claude. Plan mode is underused: use it before any large refactor or risky change to see exactly what Claude intends to do before it touches anything.
